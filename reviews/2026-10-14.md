## Worth knowing

### The harness matters about as much as the model — but the post's numbers are wrong
@qendresahhoti, https://www.instagram.com/p/DeZ4sI6hZTZ/
- **What it actually is:** a Hugging Face / Liquid AI release on multi-turn RL
  inside unmodified coding agents. The claim is that one model, unchanged, scores
  very differently depending on which agent harness wraps it — Claude Code,
  Codex, OpenCode and mini-SWE-agent were the four tested.
- **Verified — partially, and the figures don't hold up.** The work is real: the
  primary Liquid AI/HF post for **LFM2.5-2.6B** confirms a "Harness Proxy" that
  treats harnesses as black boxes while capturing token-level trajectories,
  exactly as the post describes. But that post contains **no** cross-harness
  comparison. The post claims **62% vs 33%**; secondary coverage of the
  companion guide reports **52% vs 23%** for the same-model point and
  **42.2% → 54.2%** pass@1 for the RL gain. I could not reach the guide itself,
  so **treat all these numbers as unconfirmed** — including mine.
- **Takeaway:** the direction is the useful part and it is well supported — the
  software around a model changes what it sees and how its actions run, so
  switching coding tools really can feel like the model got worse. It is also a
  point in favour of standardising on one harness rather than mixing. Do not
  repeat the 62/33 figures; they appear to be wrong.
- **Relevant to:** leadership.

### Worth knowing

#### Strix — AI pentesting against your own running app
@nick_saraev, https://www.instagram.com/p/DblTPmfPCpB/
- **What it actually is:** `usestrix/strix`, an open-source CLI that runs a set
  of LLM agents against a live app: they probe it, try exploits, and report
  each finding with a proof of concept and a suggested fix. You bring your own
  model key. The "comment CODE" gate hid nothing: the GitHub README is on screen.
- **Verified:** GitHub API 2026-10-14 — **68,390 stars** (the post says 45k, so
  it's out of date), Apache-2.0, created 2025-08-05, pushed 2026-10-13.
  SkillSpector `--no-llm` ran on a fresh clone, but most analysers came back
  "degraded" and the run produced no usable score. It is **not scanned** for
  manifest purposes, which is one more reason it stays out of `skills.json`.
- **Takeaway:** this is the closest thing seen here to an automated check on the
  "before shipping anything user-facing" list (auth enforced server-side,
  ownership on write, rate limits). Only point it at a **preview deployment of
  your own app**. It sends real attack traffic, so never use it on a client
  site without written sign-off. It needs Docker and a paid model key, and it
  is a CLI rather than a skill, so it is not in the manifest. Try it once
  against an internal tool before relying on it.
- **Relevant to:** leadership.

#### Can I Vibecode It? — buy-vs-build verdicts for ~1,000 SaaS apps
@sebastianhardy_, https://www.instagram.com/p/DdXSlJ1RGHI/
- **What it actually is:** canivibecodeit.com, open source as
  `canivibecodeit/canivibecodeit`. Each paid app gets a YES / KINDA / NOT
  REALLY verdict on whether a coding agent can build a personal replacement,
  the prompt to do it, and a list of what you lose by leaving.
- **Verified:** GitHub API 2026-10-14 — 340 stars, MIT, pushed 2026-10-10.
  `data/apps/` returns 1,000 entries, which is the API's listing cap, so the
  post's "1,100" is plausible. The site returns 200. I could not check the
  "158 single-sitting" and "10,000 prompts copied" numbers.
- **Takeaway:** the "what you lose" column is the useful part. It's a
  reasonable sanity check before cancelling a subscription. Personal
  replacements are not the same as tools a team depends on, so treat a YES as
  "a prototype is cheap", not "cancel it".
- **Relevant to:** leadership, leadership.

  rejected, not "installed with a caveat". To revisit it, run the scan with
  LLM analysis enabled (`skillspector scan … ` without `--no-llm`, needs an
