## Borderline — worth a look, not a clear yes

### 1. `ponytail` — lazy-senior-dev plugin
**Source:** @ty.prompts.ai, https://www.tiktok.com/@ty.prompts.ai/video/7679178922008857870
**Claim:** A Claude Code plugin that forces a "does this need to exist → stdlib →
native → dependency → one line → minimum code" ladder before writing code.
Benchmark: -54% LOC / -22% tokens / -20% cost / -27% time vs no-skill baseline
on 12 real feature tickets against a FastAPI+React repo (Haiku 4.5, n=4), with
safety held at 100%. The post also flags that an earlier, larger claim
(80-94% less code) was walked back publicly after a reviewer showed it was a
per-task ceiling, not the average, once a fairer agentic baseline was used.
**Verified:** yes — GitHub API confirms `DietrichGebert/ponytail`: 116,348
stars (caption said "115k"), MIT license, created 2026-06-12, pushed
2026-08-07, homepage ponytail.dev. `AGENTS.md` and the README both match the
caption's numbers and the walked-back-claim story exactly, including the
GitHub issue number (#126) that prompted the correction.
**Why it's only borderline:** This is close to word-for-word what's already
in your global CLAUDE.md — "don't add features/refactor beyond what the task
requires," "three similar lines is better than a premature abstraction," "no
half-finished implementations." The plugin operationalizes the same
philosophy via a hook rather than a prose instruction, plus a `ponytail:`
comment convention for flagging deliberate corner-cuts (global lock, O(n²)
scan) with their upgrade path — that specific piece isn't in your CLAUDE.md
today and could be genuinely useful for catching your own "I'll fix this
properly later" moments. Not proposing a diff because installing a plugin to
re-enforce a rule you already follow is a judgment call only you can make —
flagging it as an option.
**If you want it:**
```
/plugin marketplace add https://github.com/DietrichGebert/ponytail
/plugin install ponytail@ponytail
```
