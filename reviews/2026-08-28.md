## Recommended changes

### 16. `unlazy` — completion-discipline skill for long agent tasks
**Source:** @cooper.simson, https://www.tiktok.com/@cooper.simson/video/7677010451061853456
**Claim:** Transcript: "this developer built a fix for [partial compliance]…
the skill called unlazy… next time you give your agent a project, it's going to
break the plan up into smaller tasks, each with their own checklist… It also
writes a gate file, which tells the agent exactly what to look for before it's
allowed to tell you it's done." On-screen frames show a real terminal with a
`SKILL.md`-style repo browser, a "gate" checklist UI, and a Claude Code session
with a system prompt about running sub-agents in parallel.
**Verified:** **Yes** — GitHub API: `Leonxlnx/unlazy`, **2,648 stars**, MIT
license, created 2026-08-09, pushed 2026-08-24, only 2 open issues. README
confirms: install path `~/.claude/skills/unlazy`, invoked as `/unlazy`, ships a
Node-only `gate-check.mjs` (no third-party runtime deps) that runs in
`--status` (non-executing), normal, and `--approve`/`--reverify` modes. This
matches the transcript's "gate file" and "checklist" description almost
exactly — including the depth/branch parameter the video calls out ("tell it
how many branches you want" → the README's `/unlazy tree N` syntax).
**Why it fits:** This repo is itself a Claude Code automation project prone to
exactly the failure mode `unlazy` targets — an agent reporting a harvest or
analysis step as done when it silently skipped part of the work. That is a
documented risk in this project's own CLAUDE.md ("Never mark a failed item as
seen", "A step producing nothing must raise an error, not return empty"). A
gate file that forces evidence before "done" is a direct, mechanical backstop
for that class of bug.
**Caveat:** the CLI executes shell commands from `CHECK:` lines in a
gate file — read every command it prints before `--approve`, same as you would
review any script before running it. The README calls this out itself
("Security boundary").
**Proposed:**
```diff
# not a CLAUDE.md change — install as a skill:
git clone https://github.com/Leonxlnx/unlazy ~/.claude/skills/unlazy
```

## Flagged: likely fake popularity, do not trust the star count

### `ui-ux-pro-max-skill` (from post #17 below) — GitHub API contradicts itself
`nextlevelbuilder/ui-ux-pro-max-skill` shows **121,911 stars** and **13,057
forks** on a repo created 2025-11-30 (under 3 months old) — more stars than
`react` itself. But `subscribers_count` (real, non-farmable "watching" count)
is only **499**. For comparison, genuinely popular repos this size carry
watcher counts in the thousands-to-tens-of-thousands range, not 0.4% of their
star count. Fork count exceeding subscriber count by 26× on a niche prompt
pack is not organic. This is a textbook star/fork farming signature —
automated bot activity used to fake trust signals, most often to get a repo
surfaced by GitHub trending or "top starred" listicles (which is exactly the
channel that put it in front of @hasantoxr's audience). **Do not install
this repo regardless of what it claims to do.** Flagging it here specifically
because the instinct to verify-then-trust-the-number is exactly what this
process is supposed to catch, and a bare star count would have looked like a
strong signal.
